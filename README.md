
# Beyond Pattern Matching: Testing the Specificity of Mathematical Words in Human DNA

Code accompanying the paper *Beyond Pattern Matching: Testing the Specificity of
Mathematical Words in Human DNA* ([citation](#citation)).

Words generated by mathematical rules (Fibonacci, Tribonacci, Thue–Morse, period-doubling
and others) can be found in DNA once each base is read as a bit. This repository tests
whether such matches are **specific to the generating rule**, or whether any word of the
same shape (the same length, composition and run structure, or the same near-periodic
repeat) occurs just as often.

The analysis runs on the complete human genome **T2T-CHM13v2.0**.

---

## Main findings

- **Only short prefixes occur.** Of 111 prefixes from 8 word families, none longer than
  44 bits occurs anywhere in the genome in any encoding, with one exception: a single
  81-bit Tribonacci prefix in the RY encoding. This is the length at which a genome of this
  size stops producing chance matches.
- **Apparent enrichment is large but misleading.** 40 of the 333 word × encoding
  combinations occur more often than a Markov-1 background predicts (q < 0.05). The largest
  ratios belong to long, nearly periodic words with few occurrences.
- **No word beats its decoys.** Compared with decoys of the same shape, no word is enriched
  after multiple-testing correction.
- **The hits are tandem repeats.** All 3,772 loci of the enriched words were re-read from
  the genome; they lie in simple tandem repeats whose period matches the word's own
  near-period.
- **One outlier.** Tribonacci (isolate_0) T6, 44 bits, sits at the resolution limit of the
  decoy test (p = 1/101) and occurs more often than its own exact period-13 repeat.

---

## Method in brief

1. **Encode the genome as bits.** Each base is mapped to 0/1 in three ways:

   | encoding | 1 | 0 |
   |---|---|---|
   | RY (purine/pyrimidine) | A, G | C, T |
   | WS (strong/weak) | C, G | A, T |
   | MK (amino/keto) | A, C | G, T |

   Every word is searched in four forms (word, complement, reverse, reverse complement),
   which covers both strands in all three encodings. Matches never cross gaps (N) or
   chromosome boundaries.

2. **Scan** (`pattern_genome.py`). Count exact occurrences of prefixes of 13–10,000 bits of
   8 families, merge overlapping hits into clumps, and compare with i.i.d. and Markov-1
   expectations (Poisson p-values, Benjamini–Hochberg q-values). This step is a screen:
   these models produce no tandem repeats.
3. **Sequence context** (`loci_context.py`). For the enriched combinations, fetch every
   locus from the genome, verify it, and measure its tandem-repeat period.
4. **Shape-matched decoys** (`count_genome.py`). Compare 36 words (13–100 bits) with 100
   run-permutation decoys each: same length, composition and run lengths, runs in a
   different order. Hits within 1 kb are chained into one locus.
5. **Periodic decoys** (`periodic_decoy.py`). For the nearly periodic words, compare with
   other repeats of the same period carrying the same number of defects, and with the
   word's own repeat.

Empirical p-values are `(1 + k) / (N + 1)` (Phipson & Smyth 2010), so with 100 decoys the
smallest possible p is 1/101 ≈ 0.0099.

## Repository layout

```
run_all.sh               runs the full analysis, step by step
src/
  seqio.py               FASTA reading, ACGT codes, segments between gaps
  projections.py         RY / WS / MK encodings and the four search forms
  pattern_genome.py      genome-wide prefix scan, clumps, Markov expectations, p/q-values
  loci_context.py        DNA and tandem period of every locus of the enriched words
  decoy_words.py         run-permutation decoys, exact enumeration, empirical p-values
  targets.py             the 36 words used in the decoy tests, with per-word seeds
  count_genome.py        genome-wide real-vs-decoy locus counts
  periodic_decoy.py      nearest period of each word and periodic decoys
  split_t2t.sh           splits the genome into one FASTA per chromosome
tests/                   unit tests (one file per script)
notebooks/
  make_paper_figures.ipynb   main and supplementary figures from the results
data/                    input genome (not included, see below)
results/                 written by run_all.sh
```

## Requirements

- Python ≥ 3.10 with **NumPy** and **pandas** (the paper used Python 3.13, NumPy 2.1,
  pandas 2.2)
- For the figures: **matplotlib**, **seaborn** and Jupyter
- About 10 GB of free disk space
- Bash (Linux or macOS)

```bash
pip install numpy pandas matplotlib seaborn jupyter
```

## Data

Download the T2T-CHM13v2.0 assembly from NCBI (accession
[GCF_009914755.1](https://www.ncbi.nlm.nih.gov/datasets/genome/GCF_009914755.1/)) and
place the FASTA file in `data/`:

```
data/GCF_009914755.1_T2T-CHM13v2.0_genomic.fna
```

A gzipped file also works. To use another location, set `T2T=/path/to/file`.

The `split` step writes one FASTA per chromosome to `data/t2t_chroms/` (~3 GB), together
with `records.tsv`, which links NCBI record IDs to chromosome names (e.g. `NC_060925.1` ↔
`chr1`).

## Running the analysis

```bash
bash run_all.sh --list                # list the steps
bash run_all.sh                       # run everything, in order
bash run_all.sh decoys periodic       # run selected steps
WORKERS=24 bash run_all.sh scan       # settings via environment variables
```

| step | what it does | main output in `results/` | time (12 cores) |
|---|---|---|---|
| `tests` | unit tests of all scripts | `logs/tests.log` | ~2–5 min |
| `split` | one FASTA per chromosome | `data/t2t_chroms/` | ~5–10 min |
| `scan` | prefix scan, 8 families, 3 encodings, both strands | `pattern_scan_T2T.csv` | several hours |
| `context` | sequence context of enriched loci (needs `scan`) | `enriched_loci_context_*.csv` | tens of minutes |
| `decoys` | real vs run-permutation decoys (needs `split`) | `decoy_test_genome_*.csv` | minutes |
| `periodic` | real vs periodic decoys (needs `split`) | `periodic_test_genome_*.csv` | ~20 min |

Settings (environment variables, defaults in brackets): `T2T` (genome FASTA), `DATA`
[`data`], `RESULTS` [`results`], `WORKERS` [12], `N_DECOYS` [100], `PY` [`python3`].

Each step writes a log to `results/logs/<step>.log` and stops on error. Every output file
has a matching `_run.json` with its settings and software versions.

For a quick trial run before the full one:

```bash
WORKERS=4 N_DECOYS=20 bash run_all.sh tests split decoys
```

On macOS, keep the computer awake during the long scan:

```bash
caffeinate -i bash run_all.sh
```

### Figures

After the run, open `notebooks/make_paper_figures.ipynb` and run all cells. Main figures
are written to `results/paper_figures/` and supplementary figures to
`results/paper_figures/supplementary/`.

## Reproducibility

- All random choices are seeded: decoys use seed 11 (`count_genome.py`) and 23
  (`periodic_decoy.py`), with a separate stream for each word, so adding or removing a word
  does not change the decoys of the others.
- Where a word has fewer than 100 possible decoys, all of them are listed, and the smallest
  achievable p-value is reported (`testable` column).
- Each sequence family is checked against its OEIS entry in `tests/`.
